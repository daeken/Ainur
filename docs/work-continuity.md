# Accepted work continuity (source candidate, not deployed)

## Contract

Typed assignment/result/escalation inbox work is durably owed to its recipient until supported outcome, explicit disposition, or visible pause/block/wait. `assign_work` commits ownership, objective, notification and owed work in the same transaction; duplicate invocation IDs return the original assignment. Final prose and `verifying` objective labels are **not** dispatch/discharge evidence. Open/planned objectives alone never create model requests.

Assignment acceptance automatically records the assigning manager's responsibility to continue delivery. Result-to-review reuses `ReviewHandoff`: ready result, named independent reviewer assignment and receipt commit together; reviewer must belong to the receiving manager's subtree and assignment authority is that manager. Reviewer outcome durably reaches the manager. Delegating review leaves the manager waiting on the actual subordinate obligation, not silently completed. An objective marked complete settles its implementation assignment, but does **not** settle an explicitly accepted independent review of that completed artifact. Review purpose is established by the atomic `review_handoffs.action_notification_id` receipt, never notification body/dedupe text. The review remains actionable across restart until outcome/explicit disposition; canceled objectives, explicitly canceled/superseded review receipts, or canceled obligations still stop review. Both immediate inbox admission and periodic reconciliation enforce this distinction with one shared terminal predicate; pause/UNKNOWN/budget fences remain unchanged. Schema9 stores `origin_notification_id`: an immutable link to the accepted original action/receipt, independent of mutable next-action notification ID. Generated owner continuation keeps that link, and generated manager obligations inherit it. Explicit original-review cancellation/supersession therefore suppresses queued owner and manager continuations before dispatch and across restart, without suppressing unrelated legitimate result/coordination obligations. Schema7 backfill initializes the original link; alternative experimental schema9 homes are not production upgrade targets.

Startup and the existing pause-expiry timer reconcile durable work. Missing inbox wake activates the original notification, never regenerates an assignment or tool invocation. SessionHost coalesces wakes; active hosts handle their inbox without an extra watchdog wake. A consumed action left at final/idle without outcome/disposition produces **one** durable coordination continuation. If that too finishes undispositioned, status becomes stalled and the manager receives one deduplicated continuation. Each escalation level is bounded; no endless model calls on open objectives. Coordination calls still pass normal session provider/budget admission. None of this retries side effects.

Supported `disposition_work` uses the accepted notification/obligation ID. `completed`, `canceled`, `blocked`, `wait`, `wait_dependencies`, `owed` are explicit dispositions. Block/wait require both a reason and concrete resumption condition; only owner or its manager subtree can disposition. Intentional wait has no implicit timer/permission override. `owed` is an explicit coordination reactivation, not tool-replay authorization. Unknown invocation effects block automatic recovery and remain UNKNOWN/no replay; use existing lifecycle evidence to inspect/disposition, never claim success merely from tool state.

Declared prerequisites automatically hold accepted assignments at `wait_dependencies`; all prerequisite objectives must be complete before delivery. Completing a prerequisite does not dispatch unaccepted planned objectives or clear separate pause/operator/provider/budget blockers. `Store.UpdateObjective` now enforces prerequisites at completion too. An independently stored objective `blocked` stays blocked until its owner explicitly resolves it; dependency completion cannot infer that the unrelated blocker vanished.

## Supported visibility

- `GET /api/v1/projects/{id}/work`: owner, accountable manager, actual state, durable next notification, reason, resumption condition and bounded continuation ID.
- `objectives` detail and system prompt include durable obligations and explicit disposition guidance.
- Objectives UI shows accepted work separate from objective labels; no accepted obligation is explicitly distinguished from work being dispatched.
- Existing health endpoint includes readiness reason, observation timestamp, actual draining state and per-host status/activity duration/last state update. Long thinking is not proof of progress. Health considers dependency-held inbox non-runnable rather than falsely stalled.

## Observational diagnosis, not automatic release

Work status adds `obligation_state`, `owner_state`, `owner_available` (live owner with a primary session, **not** dispatch authorization), `objective_owner_id`, `ownership_differs`, `action_state`, `overlapping_unknown_count`, `age_ms`, `unchanged_ms`, `observed_at`, and `diagnostic`. `resume_condition_evaluated` is always false. Status does not wake, enqueue, reassign, alter dispositions, or interpret free-text conditions. Old age alone is never evidence a wait should be cleared.

Retired/missing owners and invalid records surface visibly. Explicit `wait`, `blocked`, `wait_dependencies`, and `wait_outcome` retain their original state/reason/resume condition on retirement or invalid-record observation. A retired owner's open work without a deliberate hold becomes stalled, or blocked if overlapping side effects are UNKNOWN. One bounded notice goes to the live accountable manager; the original action is not transferred to the objective's successor. Returning the original owner does not release an explicit wait/block/UNKNOWN. Declared dependency and subordinate-outcome waits still release only through their existing structured mechanisms, never owner availability or age.

- `intentional_wait` / `explicit_block` / `intentional_pause`: deliberate holds. Inspect the raw obligation reason and resume condition; get explicit authorized disposition. Pause release is separately authorized.
- `owner_unavailable_manual_reconciliation`: missing/retired/terminated owner or absent primary session. Compare objective owner to obligation owner; retirement may have transferred an objective, **not** accepted inbox work or side effects. The bounded manager notice requests coordination, not replay or automatic successor ownership.
- `unknown_manual_hold`: inspect the exact invocation identity and side effects; neither a generic result nor a restored owner authorizes replay. Preserve UNKNOWN until explicit safe reconciliation.
- `declared_dependencies` / `subordinate_outcome`: structured waits, distinct from free text. Investigate actual prerequisite states or exact subordinate outcome rather than guessing from elapsed time.
- `pending_dispatch` / `consumed_coordination_owed` / `missing_action_manual_reconciliation`: distinguish pending assignment from consumed-but-undispositioned work or broken linkage. Pending dispatch may still be budget/authorization/session gated. Inspect supported handoff receipt and action ID; “queued” alone does not prove review ran.

A ready artifact announced only through `decision` will not wake a reviewer, by design. Diagnose that as an absent actionable handoff, not a reason to change decisions into wakes. Use `send_message type=result reviewer=...` with an exact-source evidence body and receiving-manager authority; see `docs/review-handoff.md`. Keep native/manual implementation objectives active/verifying until independent acceptance while the native completed-artifact purpose/supersession receipt follow-up is pending.

## Migration and legacy safety

The supported lineage is schema7 → review_handoff8 → work_continuity9 → workbook10, composing continuity with image/title/transcript functionality. No gap or placeholder migration is used. Existing scratch homes carrying conflicting experimental schema8/9 contents are not supported upgrade sources. Offline tests exercise schema7 → continuity9 → workbook10 plus fresh schema10 and record preservation; they are not a live-home migration.

Schema9 backfills existing pending work as original-ID dispatch. Consumed latest notifications on nonterminal objectives become ambiguous/stalled, surfaced once to their manager, never blindly replayed. It does not treat every active/open objective as an executable obligation. Legacy root-owned ambiguity without an available manager is visible in status for explicit operator disposition. Migration runs once and exact notification IDs/dedupe keys bound escalation.

## Evidence / limits

`tests/Ainur.Tests/WorkContinuityTests.cs` is provider-free failure injection for acceptance-before-wake restart, repeated dispatch identity, consumed-final/all-owners-sleeping continuation, automatic dependency gates, blocked/paused exclusions, UNKNOWN no-replay, result→review→manager, completion/cancellation/wait, corrupt/missing target isolation, schema7 upgrade/backfill, real SessionHost delivery and HTTP health/status. Full offline command: `dotnet test tests/Ainur.Tests/Ainur.Tests.csproj --filter "Category!=Live"`; UI: `npm run build`.

No live session/restart/provider run or production migration is claimed. Independent exact-source review, accepted image/title composition, composed migration/tests and separately authorized live execution remain gates. Legacy historical obligations cannot reconstruct unknowable side effects or externally absent readiness; they require explicit disposition, not fabricated ready results.
