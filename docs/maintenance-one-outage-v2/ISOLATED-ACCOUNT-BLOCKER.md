# BLOCKER: frozen accepted runtime cannot guarantee credential-free scratch startup

Status: **NO-GO for any actual 18005e8 server process or isolated conventional rehearsal**. This is a source-only, offline audit of exact accepted `18005e8c61f61c11c4c931d3d5cd87438c231a24` (471-file image); not an installation or executable plan approval. No process, keychain, home or credential was inspected or invoked for this audit. OS, authorized operator and same service UID remain trusted; untrusted application input and accidental paid routing still require actual defenses.

## Exact source path and limitations

The independently pinned 471-file image contains `Ainur.Server.dll` SHA-256 `214D53A1CE0F79639498E8F70C8059DB8D6B4AFDC1ADF0729EBD473659DC865B` and `Ainur.Core.dll` SHA-256 `7A440EE4FC87C68ADD1C5BC472AB2C2E7E18260E8FAFC88C89D24F37B554965F`. Sources at `18005e8` have the following paths; they were cross-checked with `git show 18005e8:<path>`:

1. `src/Ainur.Server/Program.cs:5-7,25,39-44`: `--home` selects `RuntimeOptions.Home` (the DB, artifact and runtime state location); `AutoStartHosts` is false **only** with `AINUR_VALIDATION=1`; server calls `runtime.Start` even in validation mode. Health HTTP is an app API, not a provider authorization boundary.
2. `src/Ainur.Core/Runtime/AinurRuntime.cs:58-81,86-102`: constructor calls `DefaultProviders()` (registers OpenAI, DeepSeek, Zai), loads persisted agent tools, and `Start` calls `Recover` and **always** `McpLoader.LoadAsync` *before* checking `AutoStartHosts`. A scratch `mcp.json` copied from live home could execute subprocesses or network code even with validation; this is why scratch must not copy live state/keys.
3. `src/Ainur.Core/Tools/Mcp.cs:141-164` loads home-scoped `mcp.json` and starts enabled commands. `src/Ainur.Core/Tools/ReleaseTools.cs:148-159` sets `AINUR_VALIDATION=1` for a *disposable-state test*, but inherits other environment and does not disable provider registration, credential lookup or MCP loading.
4. `src/Ainur.Core/Providers/OpenAiResponsesProvider.cs:31-49,64-89` uses `Environment.SpecialFolder.UserProfile/.codex/auth.json` unless `AINUR_CODEX_AUTH` overrides it; on API-billed twins it calls `Credentials.Resolve("openai")` regardless of subscription route; no credentials/no egress has not been established. `src/Ainur.Core/Providers/Credentials.cs:21-55` reads `UserProfile/projects/FlatlineProxy/flatline.json` and can invoke `/usr/bin/security find-generic-password` against macOS keychain; changing `HOME` alone cannot prove the profile/keychain boundary. OpenAI/other HTTP clients are registered with live endpoints.
5. Published supervisor `src/Ainur.Supervisor/StrictReleaseGate.cs:38-45` creates child env with `HOME=/Users/daeken`, `AINUR_OPENAI_ROUTE=subscription`, `AINUR_SUPERVISED=1`, `PATH` and `LANG` only; it intentionally does NOT set `AINUR_VALIDATION=1`, and subscription route is NOT provider disablement. `src/Ainur.Supervisor/Supervisor.cs:197-218` calls this setting immediately before start. Current strict release pins prohibit modifying the accepted binary, appending a new environment policy or running a newly built runtime under the old release ID. Rebuilding the app to implement a fail-closed `AINUR_REHEARSAL` mode changes at least a pinned DLL hash and produces a **new, not independently accepted release**.
6. `src/Ainur.Server/Api.cs:26-30,32-52,54-59,63-66,111-127,141-149,219-229`: HTTP app exposes state-changing endpoints and health; do not send any scratch requests except authenticated health/version in a reviewed isolated boundary. No source or test in this ref proves that unauthenticated HTTP cannot induce outbound provider calls. Startup may not start hosts with validation, but this does not itself prove no credential consultation or keychain access.

## Narrow proposed OS-account capability (not yet provisioned or approved)

**Needed external capability:** an authorized operator must supply a dedicated, disposable **non-501 OS identity** and fresh private home/profile, with deny-by-OS read permission to `/Users/daeken`, its `.codex`, FlatlineProxy config and all live `.ainur`/private DB paths; no API keys in child env; a separate empty/locked user keychain; outbound egress DENIED (including DNS and all provider endpoints), permitting only controller-to-scratch-server loopback traffic on the exact scratch port. The accepted frozen image must be copied byte-for-byte to a new operator-controlled, non-group/world writable location owned by the actual scratch supervisor/service identity; all 471 manifest hashes and strict route receipt must be checked. The current `VerifyControlledInstall` rejects owner UIDs other than 0/the executing supervisor UID, so simply switching only the server child UID while keeping the controller UID 501 will fail policy and supervision. Do not relax this gate or weaken its distinct paid-route guard; an independently reviewed, exact child/supervisor UID/ownership design is a prerequisite.

The isolated account's current effective `HOME`, `.NET SpecialFolder.UserProfile`, `/Users/daeken` denial and keychain identity must be **measured inside that exact account before accepting any start**, without opening live secrets. OS-level egress denial and empty keychain/blocked home are independent backstops, not a claim `AINUR_VALIDATION` disables the provider. One isolated scratch home has a newly initialized DB, no agents, no MCP JSON, no persisted external tools and no credentials. Rehearsal must check egress-deny/network counters and provider endpoint contact attempts stay zero; exact scratch listener and process tree must be scoped; NO paid or live credential probe can be performed merely to verify the boundary. An operator must attest these facts and authorize capability provisioning; this document does **not** authorize privileged changes, execution, inspection of live profile, or a scratch server process.

**Alternative application-code approach:** add a fail-closed provider-disabled and auto-host-disabled rehearsal mode to `Ainur.Server`/`Ainur.Core` *before* `DefaultProviders`, `McpLoader`, recover/start and HTTP mutations, with explicit proof no `Credentials`, `UserProfile`, keychain or outbound network path is reached. This necessarily creates a NEW accepted full-image release/manifest/receipt; it cannot be smuggled into existing 18005e8 pins or asserted for the current frozen image. The frozen 471 image plus a variable HOME/validation flag alone cannot meet this objective.

**Decision requested from Eönwë/Yavanna:** confirm OS-account provisioning as an allowed explicit external dependency, with exact ownership/UID/process disposition, verified deny boundaries, zero egress and evidence plan, or direct production of a newly independently accepted credential-disabled full-image release. Until then the conventional controller and all executable isolated or live maintenance must remain `HOLD_NO_SPAWN`; mocks are not a substitute for a real safe process. Existing e891 source-only same-UID verdict does not authorize process start.
